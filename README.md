# Personal Asset · 项目经验资产库

**中文** | [English](README.en.md)

把做过的项目，变成下一次开发能用上的经验。

Personal Asset 是一套 **Obsidian 知识库模板与 AI 协作流程**。它帮助你从项目记录中找到值得保留的做法和教训，核对证据，经本人确认后，整理成可检索、可复用的资产。

> **人决定什么值得留下，AI 负责查重、核验、结构化和维护。**

使用 Markdown 文件和普通文件夹即可开始。Obsidian 用于查看笔记属性、双向链接和反向链接；不需要社区插件，也可以用其他 Markdown 编辑器阅读。这是文档与工作流程，不是会自动扫描项目、批准候选或写入资产的程序。

## 为什么要做这个库

项目结束后，最有价值的内容往往不是“做了什么功能”，而是：

- 什么方法有效，什么条件下才有效？
- 哪些尝试失败了，下一次怎样更早发现？
- 哪个具体问题能提炼成其他项目也能使用的检查步骤？

**复盘是起点，改变下一次的开发行为才是目的。** 适合希望积累开发经验的独立开发者、AI 从业者，以及使用 AI 辅助开发的人。

例如，本库的**虚构教学示例**从“缺失价格被当作零，错误通过预算筛选”，提炼出“先明确判断所需字段，区分缺失与有效零值，再验证边界情况”的流程。这种经验可以用于其他依赖数值的筛选场景，而不是只修补某个项目的单一功能。示例没有真实运行或收益证明。

## 快速开始

### 1. 获取模板

电脑已安装 Git 时运行：

```sh
git clone https://github.com/barronli0523/personal-asset.git personal-asset-template
```

如果已安装 GitHub CLI，也可用下面的命令替代，二选一：

```sh
gh repo clone barronli0523/personal-asset personal-asset-template
```

以上命令只获取模板文件，不会安装 Obsidian 或启动 AI。

### 2. 建立自己的工作副本

保留 `personal-asset-template` 作为干净模板，将个人内容放在独立目录。macOS / Linux 已有 Git 和 tar 时，在克隆目录的上一级运行：

```sh
mkdir my-assets && (git -C personal-asset-template archive HEAD | tar -x -C my-assets)
```

`my-assets` 必须尚不存在。该命令导出已提交的模板，不包含 `.git` 历史目录。

Windows 用户可新建 `my-assets`，复制模板文件和目录，保留隐藏文件 `.gitignore`，不复制 `.git`。也可从 GitHub 下载 ZIP，解压到独立目录。命令和手动复制步骤尚未在所有操作系统上验证。

### 3. 打开并试用

在 Obsidian 中选择“打开文件夹为仓库”，打开 `my-assets`。这里的“仓库”（Vault）就是笔记文件夹，不要求使用 Git。

先读 [AI 操作说明](AGENTS.md) 和 [目录与字段规范](30_System/schema.md)，再选择一个小项目试用。首次填模板时，将 `owner` 换成自己的名称，替换占位符并选择[已登记标签](30_System/taxonomy.md)。来源不充分的内容先留在 review，不急于生成资产。

## 如何整理一个项目

**原始材料 → 提取经验 → 查重与核验 → review 候选 → 本人批准 → 正式资产 → 下次复用**

1. **保留证据**：复用已有来源，或在 `01_Sources/` 新增原始材料或来源指针。已有来源不覆盖、不回填。
2. **提出候选**：提取成功做法、失败尝试、决策原因和环境问题；每条说明复用场景、适用条件、例外和证据。
3. **先审后入库**：查重后，一候选一条写入 `30_System/review/`。你决定收录、补证、暂缓、拒绝或确认重复。
4. **批准后落盘**：明确候选版本、目标模板、路径与动作，再进入 `10_Work/`；代表个人观点的 `20_Thinking/` 还需要本人明确确认观点。随后更新索引、记录日志并检查链接。

来自 [project-review-skill](https://github.com/barronli0523/project-review-skill) 或其他复盘流程的候选清单也走同一入口；使用本库不要求安装该 Skill。字段和状态详见[接收规范](30_System/schema.md#复盘候选接收)与 [Review 模板](30_System/templates/Review-Item.md)。

**批准收录不等于验证正确。** 条目默认 `draft`；推断和估算保留标识与依据，未知写 `unknown`。只有本人确认结论正确且证据齐全后，才标为 `verified`。拒绝候选也不等于授权删除原材料。

### 可复制的整理提示词

让能够读取本地文件的 AI 助手在你的个人工作副本中执行；否则只提供已筛选的材料。

```text
请先阅读本库 AGENTS.md 及其指定规则。
只读这个项目的资料：[项目目录或复盘报告路径]，不运行或修改源项目。
提取成功做法、失败尝试、决策原因和环境问题，并查重、核验证据。
将可复用经验一候选一条写入 review，使用既有 Review-Item 模板；
注明来源、复用场景、适用范围、例外、声明类型、隐私和推荐去向。
更新候选索引并记录日志，列出需要我决定的事项，然后停止。
未经我批准具体候选版本、目的地和动作，不写入 Work 或 Thinking。
```

## 下次开发时怎么用

先按当前问题查[索引](30_System/index.md)，只读相关经验，再将它转换成开发动作或验收条件。用完后记录结果与例外，逐渐修订资产。

```text
请按当前需求查询本地资产索引，只读相关条目。
说明每条经验为什么适用、应落实为哪些开发或验收动作；不适用的不要硬套。
优先读取资产，缺证据时再追读来源，不全量加载整个库。
不擅自增加功能、评分权重或架构；遵守目标项目的操作权限。
完成后报告使用结果、未执行项和建议修订，按授权范围更新记录。
```

有用的标准是“下次能找到，并正确用上”，不是笔记数量。AI 阅读材料会增加上下文用量，实际费用取决于使用方式；本项目不承诺未经测量的净节省。

## 目录说明

| 目录 | 放什么 | 主要边界 |
|---|---|---|
| `00_Inbox/` | 你的随手记录 | AI 不改原话 |
| `01_Sources/` | 原始证据或外部来源指针 | 仅新增，已有来源不可变 |
| `10_Work/` | 项目复盘、教训、决策、执行清单及能力说明 | 复盘候选获准后入库 |
| `20_Thinking/` | 个人观点、思维模型和洞见 | 本人明确确认 |
| `30_System/` | 规则、索引、16 种模板、review 与日志 | 规则和模板修改需授权；日志只追加 |
| `90_Archive/` | 失效但保留追溯的内容 | 移动前取得授权 |
| `examples/` | 4 篇虚构教学示例 | 不作为真实项目证据 |

## 隐私、更新与许可

- **公开模板和个人工作副本分开。** 本仓库提供方法、模板和虚构示例，不附带私人项目材料。不要把自己的整个笔记库覆盖到公开仓库。
- **分享前审查实际文件。** `.gitignore` 默认排除个人目录、日志、review 和应用状态，但不能保护已跟踪或强制添加的文件。README、索引和规则仍可能包含你后来写入的私人信息。
- **更新模板不覆盖个人内容。** 只更新干净模板目录，查看变化后再按需应用到工作副本。
- **文档语言**：README 提供中英版本；规则、模板与示例目前主要为中文。
- **许可状态**：目前未添加 `LICENSE`。公开可见不等于已授予再分发许可，许可条款仍待维护者确认。
