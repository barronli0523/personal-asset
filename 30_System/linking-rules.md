# 链接规则

使用 `[[唯一文件名]]` 连接库内笔记，必要时写 `[[文件名|显示文字]]`。公开 README 使用标准 Markdown 链接，方便 GitHub 阅读；库内笔记面向 Obsidian。

## 关系

- source：资产的证据。
- derived_from：从哪篇经验或实践提炼。
- related_project：产生于哪个项目。
- reusable_assets：项目产出了哪些独立资产。
- applies：适用场景，不表示已经实际使用。
- contradicts：证据或判断冲突，进入 review 处理。
- supersedes：经授权替代旧条目，旧条目保留。
- see_also：确实相关但不属于以上关系时使用。

建链前确认目标存在。不为了让图连通而添加无关链接；不链接未读内容。模板里的双链占位符不是正式链接，创建实例时替换或去掉不适用的可选项。已有实例出现死链时先查原因，不默默删除引用。

来源固定后不回填衍生清单；从新资产指向来源，由 Obsidian 的反向链接展示谁引用了来源。项目产出可在项目页维护，但不能改写项目历史。

认知资产从工作经验升级时新建条目，必须经人授权；旧经验保持。普通工程清单放 Playbooks，不必为了“抽象”就替人形成哲学观点。

每次新增资产更新 [[index]] 并记日志；模板和虚构示例分别登记，不算真实资产。
